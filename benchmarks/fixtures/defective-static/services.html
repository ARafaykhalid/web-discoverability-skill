A relative canonical

The canonical on this page is written as /services rather than as a full URL. A canonical is consumed away from the response that carried it, so the protocol and host have to be explicit; a path on its own names a document only for a reader that still remembers where it came from.

Exactly one finding is expected here. The path portion of the canonical agrees with the page's own path, so there is no cross-canonical to report, and the check stops at the first fault per element rather than describing the same tag twice.

Everything else on this page is deliberately correct: one title, one description, the language and viewport declared, and no images, structured data, or preview metadata at all.
