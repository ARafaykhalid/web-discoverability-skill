Release notes

Newest first. Anything that changes the meaning of an existing API response is marked as such, because a client that was written against the old meaning will not notice the difference on its own.

5 February 2026

Run history now records the warehouse query duration separately from the delivery duration. A schedule that looks slow is usually waiting on the warehouse, and the previous single number could not show that.

28 January 2026

Affects existing clients: DELETE /v1/schedules/:id now responds 404 rather than 403 for a schedule the token cannot see. The old response disclosed which identifiers existed to anyone willing to enumerate them.

14 January 2026

Workspace settings moved behind the session guard along with the rest of the application. The page had been reachable without a session, which is the fault this fixture's whole shape is built to make visible.

2 January 2026

Cron expressions accept a timezone. A weekly report that arrived at seven in the morning UTC arrived at an unhelpful hour for about half the people receiving it.

The API reference carries the current behaviour of every endpoint named above.
