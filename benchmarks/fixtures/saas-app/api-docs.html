API reference

This page is public and is meant to be indexable: developer documentation that only a signed-in visitor can read is documentation nobody finds when they need it. It is nevertheless unreachable in this fixture, because robots.txt carries Disallow: /a — written for the /app/ subtree and reaching this path as well. That is a declared defect, and it is the failure mode worth rehearsing: an over-broad crawl rule removes a public page silently, with no error anywhere for anyone to notice.

Endpoints

All four take and return JSON, and all four are versioned under /v1. Authentication is a bearer token issued per workspace.

POST /v1/schedules

Creates a schedule from a saved query identifier, a cadence expressed in cron syntax, and a list of recipients. Responds 201 with the new identifier, 409 when an identical cadence already exists for that query, and 422 when the cron expression does not parse.

GET /v1/schedules

Lists the schedules a token can see, newest first. Responds 200 with an array that is empty rather than absent when a workspace holds no schedules.

POST /v1/schedules/:id/runs

Runs a schedule immediately without disturbing its cadence. Responds 202, and the run appears in the history once the warehouse answers.

DELETE /v1/schedules/:id

Removes a schedule and keeps its run history. Responds 204, or 404 when the token cannot see that schedule — deliberately not 403, so the endpoint does not disclose which identifiers exist.

Rate limit

Sixty requests a minute per token. The limit is returned on every response so a client can pace itself rather than discover the ceiling by hitting it.

See the release notes for changes to any of this, and sign in to issue a token.
