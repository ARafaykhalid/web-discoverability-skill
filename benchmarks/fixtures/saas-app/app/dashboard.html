This is the first response the server sends for an authenticated dashboard: the navigation, the heading, and the explanation below arrive in the initial HTML, and the table of schedules is filled in afterwards from the workspace API once the session is confirmed in the browser.

The split is deliberate in this fixture, and it is shaped to be unremarkable: the initial response already carries the title, the heading, and most of the words, and the canonical is byte-identical before and after execution. Nothing measures that here - the two JavaScript-rendering requirements are gated on a client-rendered or JavaScript application, and this is static HTML - so the pair exists to make the initial and executed documents genuinely different strings, not to earn a pass. A shell that carried none of that content would be a different fault, and it belongs in a different fixture rather than being smuggled in here.

Nothing on this page is public. It requires a session, the guard at middleware/session.js redirects an unauthenticated request to the sign-in page, and the capture records it as not indexable so that the noindex above is read as intent rather than as an accident.
